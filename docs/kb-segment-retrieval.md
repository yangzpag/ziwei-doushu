# 知识库 · 语义段落检索（kb）

> 状态：**v1 已上线**（2026-10-15）。页面：`/kb`（顶栏「中医知识库」进入）。
>
> 定位（用户原始需求）：按段落检索视频讲课内容，每个段落带视频起止时间；
> 用户先读段落摘要判断要不要看，点时间点跳转 B 站那一秒。

## 数据流（对齐用户规格）

```
句子序列（corpus_entry：quote + t_hms，每条带 h2 话题标注）
  → 语义分段（当前：按 h2 话题分组 —— 语料作者已标好边界）
  → 段落 kb_segment {segment_id, video_id, title, text, start_seconds, end_seconds, embedding}
  → 段落级 embedding（bge-small-zh，标题+正文头部截断 1800 字）
  → 检索命中 → 点击跳转 start_seconds（程序生成 B 站链接）
```

段落表 `kb_segment`（767 段 / 19,294 句）：`start_seconds` = 组内首句 t_hms，
`end_seconds` = 末句 t_hms（摘录无结束时间，取末句时刻）。
**分段边界目前来自语料 h2 标注**；完整字幕到位后改由语义分段器填充
（LLM 输出 `{title, start_sentence_id, end_sentence_id}` → 程序拼句子读时间戳，模型不碰时间）。

## 智能路由（查库 or 直答）

**v2（2026-10-15）：改为 LangChain agent**（`lib/kb/agent.ts`）——
`createAgent` + `search_course_segments` 工具，模型自主决定调不调检索、用什么关键词（tool calling），
佐证段落经工具闭包累计；检索轮数上限 3（工具内强制）；上下文已有段落清单注入 agent 视野（追问不重复检索）；
每轮思考/检索通过 `trace` 事件透出（前端可视化 loop 过程）。历史上下文随请求传递（最近 6 轮），服务端不落库。
agent 运行失败自动回退规则路由（下表），行为不劣化。

规则路由（兜底 + 校准依据）：双信号设计（`lib/kb/router.ts`），校准数据：相关问题 top-1 相似度 0.58-0.72，
无关/跨域 0.31-0.56（有重叠带）：

| 分数带 | 动作 |
|---|---|
| ≥ 0.62（KB_RAG_HIGH） | 直接走 RAG |
| ≤ 0.40（KB_DIRECT_LOW） | 直接回答（不查库） |
| 中间地带 | LLM 二分类（deepseek-flash，6s 超时；失败偏保守走查库） |
| 问题点名课程（倪师/本草经/条文…） | 关键词直通 RAG |

走了 RAG 但 top-1 < 0.45（KB_NO_HIT）→ 明说「库内没有相关内容」+ 通用回答兜底。

## 混合检索

`lib/kb/search.ts`：向量 Top-K ∪ **标题命中**（问题里点名段落主题，
如「条336讲什么」→「条336」，加分到 0.72；数字边界防「条1」误中「条117」）。

## 回答与引用

- RAG 命中：LLM 只依据给定段落生成回答，论点挂 `[1][2]` 引用编号 → 前端渲染为可点击角标，
  点开即跳对应段落的 B 站时间点；回答下方列出引用段落卡片（标题/课程/时间区间/相似度/▶回放）
- **AI 不可用时自动降级**（当前沙箱网络到 DeepSeek 时通时断）：`aiAvailable=false`，
  答案降级为命中段落原文拼接，角标和跳转照常可用——检索与跳转不依赖 LLM

## 已知限制（如实记录）

1. **摘录非完整逐字稿**：段落文本是抽样拼接（约 1/8 覆盖），读感有断层；完整内容需点回放。前端已标注。
2. **段落粒度 = h2**：一个药材/条文一段（最长 16 分钟），偏粗；h2 内部子话题切分是语义分段的下一步试验田。
3. **LLM 网络依赖**：AI 综合回答需要能访问 DeepSeek 端点；不通时自动降级（见上）。
4. **中间地带 LLM 分类不稳定**：分类调用 6s 超时，网络差时回退「偏保守走查库」——无关问题可能被查一次库（但回答仍会明说库内没有）。
5. 「条336」式精确主题已用标题命中解决；同义改写（如「拉肚子」vs「下利」）仍靠向量语义，是主要调优空间。
