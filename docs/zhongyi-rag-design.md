# 中医知识库 · RAG 生成式回答设计（倪海厦《人纪》语料）

> 状态：**设计中，待 review**（2026-10-14）
> 关联：REPOLAYOUT.md（架构）/ CODESTYLE.md（约定）/ 语料 nihai-renji-corpus（CC BY-NC-SA 4.0）

---

## 1. 背景与目标

### 1.1 当前形态（纯检索直检）

```
问「湿疹」→ pgvector 语义检索 Top60 → 按(条文,类型,集数)聚 3 组原文判语 → 堆叠展示
```

**局限**（用户实测反馈）：
1. **准确度**：纯向量召回漏字面精确匹配的长尾（「湿疹」漏了「蛇床子…阴湿湿疹的痒」——已通过混合检索临时缓解）
2. **无总结**：用户要的是「**湿疹有哪些草药 → 每味药的属性/用法总结 + 视频引用**」，不是原文堆
3. **追问断裂**：检索无状态，「这个药怎么用」丢失指代（已有 LLM 改写缓解，但链路不完整）
4. **无原著交叉**：语料 100% 是讲座口语，用户要找《神农本草经》原文对照（语料后续接入）

### 1.2 目标形态

```
问：湿疹有哪些草药？
答：· 蛇床子 [1] —— 味苦性平，主阴湿湿疹之痒；外洗或入丸散 [1]
     · 苍术 [2]   —— 健脾燥湿，湿盛者必用 [2]
     · 黄连 [3]   —— 湿热盛者用之 [3]
     （[n] 点开 → 那一秒的 B 站视频）
追问：蛇床子打粉还是煎服？
答：（自动知道"蛇床子"指上一轮那味药）…… [4][5]
```

关键词：**结构化总结 + 引用溯源 + 连续追问**；后期叠加**古籍原文交叉**。

## 2. 总体架构：两段式 RAG（不急着上全自动 Agent）

```
用户问题（带最近 6 轮 history）
   │
 ① 改写（已有，lib/corpus/rewrite.ts）
   │   DeepSeek 补指代 + 判断问题类型：单点 / 列表 / 原文诉求
   ▼
 ② 检索路由
   ├─ 单点问「蛇床子怎么用」   → 实体反查（kb_entry_entity）+ 向量排序
   ├─ 列表问「湿疹有哪些药」   → 上下文判语 → 实体关联聚合 → 每个实体取代表判语
   └─ 降级：实体索引未命中     → 混合检索（向量 ∪ 关键词，已有）
   ▼
 ③ 生成（lib/corpus/synthesize.ts，SSE 流式）
   │   LLM 只依据检索到的判语总结，强制 [n] 引用标注；失败 → 退回纯检索展示
   ▼
 ④ 前端：结构化卡片渲染
   │   药名 / 属性（倪师讲的）/ 用法总结 / [n] 引用 → 侧滑回放
   ▼
 ⑤ 追问：history + 改写（已有）
```

**为什么不上全自动 Agent（工具调用）**：
- 实体索引用结构化数据比让 LLM 猜更准、更便宜、可观测
- 两段式每步可独立降级（LLM 挂 → 纯检索；embed 挂 → 关键词），不会整体瘫
- 每问成本可控（见 §7），Agent 多轮规划成本不可控
- 实体索引验证充分后，可把「多路检索」收敛为 Agent 自主规划（Phase 3+ 再评估）

## 3. 详细设计

### 3.1 实体索引（P0，语料预处理核心）

**词典来源**（全部公有领域知识，内置为种子数据，不依赖外部 API）：

| 类型 | 数量 | 内容 |
|---|---|---|
| herb | 365 + 增补 | 《神农本草经》上中下三品全量 + 倪师常用增补（如蛇床子、黄连） |
| formula | ~120 | 伤寒论 + 金匮要略方剂（桂枝汤、真武汤…） |
| acupoint | ~360 | 十四经经穴（足三里、肺俞…） |

本期建 herb；formula/acupoint 同架构，Phase 2 补。

**表结构**（Neon PG，与 corpus_* 同库）：

```sql
CREATE TABLE kb_entity (
  id       serial PRIMARY KEY,
  type     varchar(16) NOT NULL,     -- herb / formula / acupoint
  name     varchar(32) NOT NULL,     -- 标准名（蛇床子）
  aliases  text[],                   -- 别名（蛇米、蛇珠…）
  attrs    jsonb,                    -- 性味归经等结构化属性（原文接入后填，见 §3.4）
  UNIQUE (type, name)
);

CREATE TABLE kb_entry_entity (
  entry_id  bigint REFERENCES corpus_entry(id),
  entity_id int    REFERENCES kb_entity(id),
  PRIMARY KEY (entry_id, entity_id)
);
CREATE INDEX kb_entry_entity_entity ON kb_entry_entity(entity_id);
```

**匹配规则**（防误命中）：

1. **全名匹配**——单字药名（术/麻/桂/芍）不单独匹配，必须全名（苍术/白术/麻黄/桂枝）
2. **长词优先**——「附子汤」命中时同时记 formula=附子汤 与 herb=附子
3. **别名参与**——「蛇米」→ 蛇床子
4. Trie 多模匹配，19,294 条一次扫描（秒级），**幂等可重跑**（truncate 重建）

**交付物**：

```
scripts/kb/entities/herbs.json       # 365+ 味药词典（标准名/别名）
scripts/kb/entity-tables.sql         # 上面两张表
scripts/kb/build-entity-index.mjs    # Trie 匹配 + 幂等重建
```

**查询模式**：

| 问题类型 | 查法 |
|---|---|
| 列表问「湿疹有哪些药」 | ① 找湿疹相关判语（混合检索）② `JOIN kb_entry_entity` 聚合药名按频次 ③ 每药取代表判语 |
| 深追问「蛇床子怎么用」 | ① kb_entity 定位 ② 反查全部判语 ③ 向量排序取 top ④ LLM 总结 |
| 实体索引未命中 | 退回混合检索（现有链路） |

### 3.2 生成式回答（Phase 1 核心）

**接口**：`POST /api/zhongyi/chat`（SSE 流式，与 `/api/interpret` 同款模式）

```
请求 { q, book?, history? }
响应  SSE 事件序列：
      · {type:'meta',  rewritten, entities:[蛇床子,苍术…], groups:[引用组]}   # 先出引用侧栏素材
      · {type:'delta', text}  × N                                            # 流式正文（含 [n] 引用编号）
      · {type:'done'}
```

**Prompt 约定**（严格约束，防幻觉）：

```
你是「倪海厦《人纪》中医课程」学习助手，依据课程判语回答学员提问。
1. 只能依据下方判语作答；判语没讲的，明说「课程里没有讲到这个」，禁止外用知识
2. 引用判语在句末标 [n]；一段话可引多条
3. 先一句直接回答，再分点展开；语气像助教，平和简短
4. 不编造方剂、穴位、条文；涉及健康建议时提醒「仅供学习参考，不构成医疗建议」
5. 若问题是「有哪些X」类，先列出名称清单，再逐一概述
```

**结构化卡片**（前端，用户已选定形态）：
- 卡片字段：药名 / 倪师讲的属性 / 用法总结 / [n] 引用（点击侧滑回放）
- 渲染来源：LLM 输出的结构化 JSON（`{items:[{name, attrs, usage, refs:[1,3]}]}`），正文仍可含引导句
- **降级**：LLM 失败/超时 → 展示现有纯检索分组（模式标注「语料直检」）

### 3.3 追问与历史（已有，纳入体系）

- `rewriteQuery(question, history)`：补指代（「这个药」→「蛇床子」）+ 原文意图识别
- history 取最近 6 轮（user 问 + AI 引用主题摘要），localStorage 持久化（已有）

### 3.4 神农本草经原文交叉（Phase 3，用户提供语料后）

```
新表 corpus_classic（古籍原文）：
  id / classic(本经|伤寒论|金匮…) / chapter(篇/卷) / title(条目名) / text(原文) / embedding

交叉展示：
  ┌─────────────┬─────────────┐
  │ 倪师讲座讲解  │ 古籍原文     │
  │ 「蛇床子味苦  │ 「蛇床子：味苦，│
  │  主阴湿之痒」 │  主阴湿疮痒…」 │
  │  [1] 回放     │  出处：本经·草 │
  └─────────────┴─────────────┘
```

- `kb_entity.attrs`（性味归经）从原文结构化填入
- 检索时双库并查，讲座判语与原文按实体对齐展示
- **原则**：原文只从用户提供的权威语料入库，不由 LLM 生成（防篡改古籍）

|---|---|---|---|
| **Phase 1** | 生成式回答：改写 → 混合检索 → SSE 流式总结（结构化卡片 JSON）+ 引用侧栏；纯检索降级 | 已有混合检索/改写；DeepSeek key | 无头浏览器：问「湿疹有哪些草药」出卡片+引用；追问指代正确；LLM 挂时降级 |

## 7. 成本与降级

**每问 LLM 成本**（DeepSeek flash）：

| 调用 | 次数 | 说明 |
|---|---|---|
| 追问改写 | 1 | 已有；失败用原问题 |
| 生成总结 | 1 | Phase 1 新增；输入 = 问题 + 检索判语（≤12 条 × 30 字）；输出 ≤800 字 |

≈ 每问 2 次 flash 调用，成本可忽略；不计入用户次数权益（知识库免费功能）。

**降级链**：LLM 生成失败 → 纯检索分组展示；embed-server 挂 → 关键词检索；实体索引空 → 混合检索。

---

## 8. 风险

| 风险 | 缓解 |
|---|---|
| LLM 编造影射之外的药性 | Prompt 严格约束「只依据判语」+ 引用标注可溯源 + 降级展示原文 |
| 列表问聚合不准（频次≠主次） | 频次 + 向量分双排序；卡片允许 LLM 判断主次 |
| 古TCM 术语 ASR 噪声 | P2 纠错 pass；引用回放自证 |
| 流式生成延迟 | meta 事件先出引用侧栏，正文流式跟进的渐进体验 |
